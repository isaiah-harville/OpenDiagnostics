# Model projects

Each directory here is one model on one benchmark. The shared code lives in
`src/opendiagnostics`; a project holds only what is specific to it.

```
models/<dataset>-<model>/
  config.yaml       the experiment; `uv run opendiagnostics fit -c models/<name>/config.yaml`
  MODEL_CARD.md     intended use, data, training, results with CIs, limitations
  baselines.yaml    published results on the same benchmark, with sources
  runs/<run-id>/    published runs: small files in git; artifacts.yaml links the weights
```

The lab notebook (`uv run opendiagnostics notebook`, then `uv run zensical serve`) renders every
project and run from these files.

## Adding a project

1. Copy `_template/` to `models/<dataset>-<model>/`. The MedMNIST projects' configs
   (`*-convnext` and `*-resnet18`) are generated by `scripts/medmnist_recipes.py`, and the
   `*-dynunet` segmentation projects' by `scripts/segmentation_recipes.py`; edit the script,
   not their configs.
2. Point `data` at a data module (`MedMNISTDataModule`, `CSVImageDataModule`,
   `BoxManifestDataModule` for detection, or `NiftiSegmentationDataModule` for segmentation)
   or a `MedicalDataModule` subclass of your own.
3. Use `split: patient` unless the benchmark has an official patient-disjoint split.
   Use the official split whenever you compare with published results.
4. Write `baselines.yaml` with the published numbers you mean to beat: same split, same
   metric, with a source for each. See [docs/design.md](../docs/design.md#beating-published-results).
5. Check the dataset's license allows what you publish. Credentialed data (PhysioNet, for
   example) may forbid sharing derived weights or per-image predictions. See
   [docs/datasets.md](../docs/datasets.md).

## Publishing a run

1. Commit your changes, then train. A run on a dirty tree cannot be reproduced from its
   commit, and `opendiagnostics publish` refuses it.
2. `uv run opendiagnostics publish runs/<name>/<run-id> models/<name>`. Add `--no-predictions`
   when the license forbids sharing per-image outputs.
3. To compare with an earlier run on the same split:
   `uv run opendiagnostics compare <old>/predictions_test.csv <new>/predictions_test.csv`.
4. Update the model card from the run's `metrics.json`, commit, and rebuild the notebook.
5. When the dataset's license allows sharing weights, publish uploads the checkpoint to the
   public weights bucket and records its URL. That needs the publisher key; see
   [docs/weights.md](../docs/weights.md#publish). Pass `--no-checkpoint` to publish
   without the weights.

The `*mnist-convnext` projects cover the twelve MedMNIST 2D subsets at 224 px, and the
`*-resnet18` projects the six 3D subsets at 64³. The 3D projects have no published run yet.
`nih-chestxray14-convnext`, `kermany-oct-convnext` and `kermany-cxr-convnext` train on the
full-resolution source images at 448 px; download each dataset first with the script named
at the top of its config. None of the three has a published run yet.
`pu2756-convnext` trains on PU2756 lung ultrasound under its official five-fold
cross-validation, one fold per run (`--data.init_args.split_column=foldN`); it has no
published run yet.
The `*-dynunet` projects segment KiTS23, the ten Medical Segmentation Decathlon tasks,
TotalSegmentator, ACDC and PI-CAI. Download each dataset first with its script in
`scripts/datasets/`, which writes the manifest the config reads; none has a published run.
